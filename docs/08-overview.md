# 1부 · 이게 무슨 프로젝트인가

## 1.1 한 문장

**이주노동자가 안전교육을 "이해했는지" 글자 없이 확인하고, 그 기록을 그대로 법정 교육 증빙으로 만드는 서비스.**

## 1.2 어떤 문제에서 출발했나

산업안전보건법은 사업주에게 정기 안전교육을 의무로 지웁니다.
그리고 교육을 했다는 증거로 **참석자 서명부**를 남깁니다.

문제는 이겁니다.

> **서명은 "그 자리에 있었다"는 증거일 뿐, "이해했다"는 증거가 아닙니다.**

한국어를 못 읽는 이주노동자에게 한국어 교육 자료를 주고 서명을 받으면,
서류는 완벽하지만 **그 사람은 아무것도 이해하지 못한 채 위험한 설비 앞에 섭니다.**
그리고 사고가 나면, 서류상으로는 교육을 다 한 상태입니다.

이 프로젝트는 그 사이의 빈칸을 메웁니다.

| 지금 현장 | 이 서비스 |
|---|---|
| 한국어 자료 + 서명 | 노동자의 **모국어 음성** + 그림으로 된 이해도 확인 |
| "교육을 했다" 만 기록 | **"무엇을, 어느 언어로, 얼마나 이해했는지"** 기록 |
| 증빙 작성에 몇 시간 | 화면에서 바로 인쇄 |
| 사고가 난 뒤에야 통계 | **위험요소 익명 신고**로 사고 전에 신호 |

## 1.3 왜 "글자를 못 읽어도" 가 핵심인가

이 서비스의 대상은 **입국 3개월 차, 한국어를 거의 못 읽는 노동자**입니다.
그래서 모든 설계가 여기서 나옵니다.

- 모든 안내에 **음성이 함께** 나갑니다 (노동자 화면 전부)
- 이해도 검증 문항은 **글로 답하지 않습니다** — 세 유형 전부 손가락 조작입니다

| 유형 | 무엇을 하나 |
|---|---|
| 👆 `hotspot` | 설비 그림에서 **위험한 지점을 짚기** |
| ☑ `choice` | **올바른 작업을 고르기** |
| 🔗 `match` | **보호구를 알맞게 연결하기** |

- 상태 표시는 **아이콘 + 글자 + 색 세 가지를 동시에** 씁니다 (흑백으로 봐도, 색약이어도 통함)
- 버튼은 **60×60px 이상** — 장갑 낀 손으로 누릅니다

> **이 원칙이 깨지면 이 제품은 존재 이유가 없습니다.**
> *"문항이 글로 돌아가는 순간 기능4는 기존 필기시험이 된다"* 가
> 코드 주석에 그대로 적혀 있습니다.

# 2부 · 전체가 어떻게 이어지는가

## 2.1 하나의 흐름

이 서비스의 9개 기능은 따로 노는 게 아니라 **한 줄로 이어집니다.**
앞이 비면 뒤는 만들어도 화면에 아무것도 안 뜹니다.

```
① 담당자가 사업장·공정·설비·쓰는 언어를 등록한다          (기능1)
        ↓
② 운영자가 안전 문구의 번역을 검수한다                     (기능9)
   — 승인된 문구만 안전 지시로 나갈 수 있다
        ↓
③ 담당자가 검수된 문구를 골라 교육을 만들고 문항을 붙인다   (기능2)
        ↓
④ 노동자가 자기 언어 음성으로 교육을 듣는다                (기능3)
        ↓
⑤ 이해했는지 그림으로 확인한다                            (기능4) ★ 제품의 심장
        ↓
⑥ 담당자가 "어느 항목에서 다들 막혔는지" 를 본다           (기능6)
   → 교육을 고친다 → ③으로 돌아간다 (개선 루프)
        ↓
⑦ 감독기관에 낼 증빙을 인쇄한다                           (기능5)

  그리고 상시로:
  · 노동자가 위험요소를 익명으로 신고한다                  (기능8)
  · 현장 공지·질문을 주고받는다                           (기능7)
```

## 2.2 이 흐름에서 특별한 두 지점

**하나 — 운영자 검수(②)가 병목이자 안전장치입니다.**

검수되지 않은 번역은 **화면에 뜨지도 않습니다.** 답답해 보이지만 이유가 있습니다.
번역에서 부정문이 뒤집히면 *"보호구를 착용하지 마시오"* 가 됩니다.
**오역이 그대로 사고가 됩니다.**

예시 데이터에 실제로 그런 문구(`ph-3`)가 들어 있습니다 —
인도네시아어 번역만 뜻이 뒤집혀서 **그 언어만 중지**돼 있고,
크메르어 노동자는 같은 문구를 계속 듣습니다.
*"뜻이 뒤집힌 그 언어만 내렸고, 다른 언어 노동자는 이 안전 지시를 계속 받습니다"* —
이게 시연에서 가장 잘 보여 주는 장면입니다.

**둘 — 미통과는 노동자의 실패가 아니라 교육의 실패로 다룹니다.**

이해도 검증에서 떨어져도 화면은 노동자를 탓하지 않습니다.
담당자 대시보드에도 *"개인 평가가 아니라 콘텐츠 개선 신호"* 라고 적혀 있고,
**인사·평가 목적으로 점수를 내보내는 기능은 아예 만들지 않았습니다.**

# 4부 · 어떻게 만들어져 있나 (기술)

## 4.1 한마디로 — "빌드가 없는 정적 웹"

| 항목 | 이 프로젝트 |
|---|---|
| 언어 | HTML · CSS · **바닐라 JavaScript** (React 같은 프레임워크 없음) |
| 빌드 | **없음.** `npm install` 도 `node_modules` 도 없음 |
| 서버 | **없음** |
| 데이터베이스 | **없음** — 브라우저 저장소만 |
| 외부 요청 | **0건.** CDN · 웹폰트 · 외부 이미지 없음. 픽토그램은 전부 이모지 |
| 코드 분량 | `src/` 약 **11,900줄** · 검사 코드 약 **3,100줄** |

## 4.2 왜 이렇게 만들었나 — 이상해 보이지만 이유가 있습니다

**요즘 방식(프레임워크 + 서버 + DB)이 아닌데, 일부러 그랬습니다.**

1. **`src/index.html` 을 더블클릭하면 그게 바로 완성된 앱입니다.**
   설치도, 서버 실행도, 인터넷도 필요 없습니다.
   → 확인이 **몇 초**만에 끝납니다. 팀원 누구에게든 폴더만 주면 됩니다.
2. **인터넷이 약한 현장이 실제 사용 환경입니다.**
   외부 요청이 0건이라 통신이 끊겨도 화면이 깨지지 않습니다.
3. **의존성이 0이라 썩지 않습니다.**
   패키지 업데이트로 갑자기 안 돌아가는 일이 없습니다.

이 선택 때문에 지켜야 하는 규칙이 생겼습니다 —
**ES 모듈(`import`/`export`) 금지.** `file://` 로 열면 브라우저 보안 정책에 막힙니다.
실제로 그렇게 만들었다가 되돌린 기록이 개발일지에 있습니다.

## 4.4 눈여겨볼 만한 부분

- **설비 그림을 이미지 파일로 두지 않고 코드로 그립니다** (`diagrams.js`).
  외부 이미지 요청이 0건이어야 하고, 화면 크기에 따라 안 깨져야 하기 때문입니다.
  "위험 지점 짚기" 의 좌표는 **퍼센트로** 저장합니다 —
  폰 화면 크기가 달라도 정답이 어긋나지 않게.
- **번역 검수에 "역번역 대조" 가 들어 있습니다** (`review.js`).
  번역문을 다시 한국어로 옮긴 것과 원문을 비교해서 **부정문이 뒤집혔으면 크게 경고**합니다.
  낱말이 조금 다른 것과는 세기를 다르게 표시합니다 —
  똑같이 경고하면 운영자가 경고를 무시하게 되고, 정작 뜻이 뒤집힌 게 지나갑니다.
- **정답이 어긋나는 사고를 한 곳에서 막습니다.**
  문항의 정답은 "몇 번째 선택지" 라는 번호로 저장됩니다.
  번역한 선택지 개수가 원문과 다르면 **정답이 엉뚱한 것을 가리키고, 틀린 작업을 맞다고 가르칩니다.**
  그래서 그 검사를 `store.js` 한 곳에만 두고, 화면들은 반드시 그 통로로만 문항을 읽습니다.
- **음성이 안 나면 그 사실을 화면에 적습니다.**
  크메르어 음성이 깔린 안드로이드는 흔하지 않습니다.
  소리가 안 났는데 난 줄 알면, **글자를 못 읽는 사람은 아무것도 못 받은 채 통과합니다.**

# 5부 · 데이터가 어떻게 저장되나 ★ 중요

## 5.1 지금은 — 브라우저 안에만 있습니다

데이터베이스가 없습니다. 모든 데이터는 **웹브라우저가 자기 안에 가지고 있는 작은 저장 공간**
(`localStorage`)에 들어갑니다.

**이것이 이 프로젝트를 이해하는 가장 중요한 지점입니다.** 여기서 생기는 일:

| 현상 | 왜 그런가 | 고장인가? |
|---|---|---|
| PC 에서 넣은 데이터가 **폰에서 안 보인다** | 기기마다 저장소가 따로 | **정상** |
| 배포 주소와 내 PC 파일의 데이터가 **다르다** | 주소(오리진)마다 저장소가 따로 | **정상** |
| 시크릿 모드에서 껐다 켜면 **사라진다** | 브라우저가 지움 | **정상** |
| 사진을 몇 장 넣으면 **꽉 찬다** | 용량이 약 5MB | **정상 (한계)** |

> **발표 때 다른 사람 폰으로 열면 원래는 빈 화면입니다.**
> 그래서 처음 여는 사람에게는 **예시 데이터가 자동으로 채워지게** 만들어 뒀습니다.
> 실제 데이터를 기기 사이로 옮겨야 하면 사업장 등록 화면의
> **내보내기 / 불러오기** 로 JSON 파일을 복사합니다.
> 서버 없이 두 기기 시연을 하는 유일한 방법입니다.

## 5.2 데이터 8칸 — 사실상의 "DB 테이블"

서버가 생기면 그대로 테이블 8개가 될 구조입니다.

| 저장소 | 무엇이 들어가나 | 누가 쓰나 | 누가 읽나 |
|---|---|---|---|
| `accounts` | 계정 (아이디·역할·언어) | 회원가입 | 로그인 |
| `session` | 지금 로그인한 사람 | 로그인 | 모든 화면 |
| `setup` | 사업장·언어·공정·설비·노동자 | 기능1 | 거의 모든 화면 |
| `library` | 안전 문구와 **언어별** 검수 상태 | 기능9 | 기능2 · 기능3 |
| `courses` | 교육과 문항 | 기능2 | 기능3 · 기능4 |
| `progress` | 누가 무엇을 듣고 몇 점인지 | 기능3 · 기능4 | 기능5 · 기능6 |
| `reports` | 위험요소 신고 (**익명**) | 기능8 | 기능6 |
| `posts` | 게시글·댓글 | 기능7 | 기능7 |

## 5.3 ★ 서버·DB 를 나중에 붙일 수 있게 만들어 둔 장치

**화면 코드는 브라우저 저장소를 직접 부르지 않습니다.**
반드시 `Store` 라는 중간 통로를 거칩니다.

```
[화면 11개]  →  [ Store ]  →  지금: 브라우저 저장소
                    ↑
              서버가 생기면 이 안쪽만 서버 호출로 바꿉니다.
              화면 11개는 한 줄도 안 고쳐도 됩니다.
```

이게 이 프로젝트에서 가장 값진 설계 결정입니다.
**브라우저 저장소를 직접 부르는 코드가 저장소 전체에 단 한 곳(`store.js`)뿐인지를
자동 검사가 매번 확인합니다.** 어기면 검사가 빨간불이 납니다.

## 5.4 실제로 DB 를 붙이면 무슨 일이 벌어지나

"전체 개발이 완료되면 어떤 모습인가" 의 핵심이 이 단계입니다.

### 바꿔야 하는 것

| 순서 | 무엇 | 설명 |
|---|---|---|
| 1 | **서버 함수(API)** | Vercel 에 서버 코드를 올립니다. 지금 배포 구조를 그대로 쓰면서 폴더 하나를 추가하는 형태라 **배포 방식 자체는 안 바뀝니다** |
| 2 | **데이터베이스** | 관리형 PostgreSQL 을 붙입니다. 위 8칸이 그대로 **테이블 8개**가 됩니다 |
| 3 | **`store.js` 안쪽 교체** | `load()` `save()` 를 서버 호출로 바꿉니다. **화면 11개는 그대로** |
| 4 | **진짜 로그인** | 지금은 비밀번호가 브라우저에 그대로 있는 **가짜 인증**입니다. 서버에서 암호화·세션 발급으로 바꿔야 합니다 |
| 5 | **파일 저장소** | 신고 사진·음성 메모를 담을 곳. 브라우저 저장소로는 불가능한 부분입니다 |

### 그러면 비로소 되는 것

- 담당자 PC 에서 만든 교육을 **노동자 폰에서 바로** 볼 수 있습니다 (지금은 불가능)
- 여러 사업장이 동시에 씁니다
- 데이터가 안 날아갑니다. 브라우저를 지워도 남습니다
- 신고에 **사진**을 붙일 수 있습니다
- **기한이 다가오면 알림**을 보낼 수 있습니다 (지금은 담당자가 대시보드를 열어야만 압니다)
- 설비 앞 **QR** 이 진짜 의미를 가집니다
- 오프라인 대응(네트워크가 끊겨도 동작)을 붙일 수 있습니다

### 그때 잃는 것 — 미리 알아 둘 것

- **더블클릭으로 여는 확인 방법이 사라집니다.** 지금 가장 빠른 검증 수단입니다
- 인터넷 없이 동작하지 않습니다 → 오프라인 대응이 **별도 과제**가 됩니다
- 개인정보를 서버에 담게 되므로 **보안·법적 책임이 실제로 발생**합니다

> **지금 서버를 안 붙인 것은 게을러서가 아닙니다.**
> 서버 없이도 **제품의 핵심 주장(이해도 검증)을 전부 증명할 수 있고**,
> 붙일 자리는 미리 만들어 뒀습니다.
> *"사진이 필요해지는 시점이 곧 서버가 필요해지는 시점"* 이 이 프로젝트의 기준선입니다.

2. **올린 뒤 주소를 실제로 열어서 확인합니다.** "push 됐다" 는 "배포됐다" 가 아닙니다.

- 외부 요청이 **0건**인지, `innerHTML` 을 쓴 파일이 없는지
- 브라우저 저장소를 **직접 부르는 코드가 `store.js` 밖에 없는지**

> **왜 이렇게까지 하나** — 혼자 개발하면 원칙은 조용히 무너집니다.
> "이번만 예외로" 가 쌓이면 어느 순간 다른 제품이 되어 있습니다.
> 그래서 **원칙을 문서가 아니라 검사로** 박아 뒀습니다.
