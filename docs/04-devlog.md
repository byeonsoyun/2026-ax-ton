# 04. 개발일지

## 왜 쓰나

개발하다 보면 **일주일 뒤에 내가 뭘 만들었는지 기억이 안 납니다.**
Claude Code 로 만들면 더 그렇습니다. 화면은 나왔는데 어떻게 나온 건지 모르는 상태가 됩니다.

개발일지는 그때를 위한 기록입니다. 세 가지에 쓰입니다.

1. **발표 준비** — 2분 대본을 쓸 때 이 파일이 재료가 됩니다. "우리가 뭘 만들었나"를 여기서 뽑습니다
2. **이어서 하기** — 며칠 만에 다시 앉았을 때 어디까지 했는지 5초 만에 압니다
3. **막힌 것 공유** — 같은 문제를 다른 팀원이 또 만나면, 이미 푼 방법이 여기 있습니다

---

## 어떻게 쓰나

**직접 안 써도 됩니다.** Claude Code 가 알아서 적습니다.

저장소의 [`CLAUDE.md`](../CLAUDE.md) 에 "commit 하기 전에 개발일지에 한 줄 추가" 규칙이 있어서,
한 덩어리가 끝날 때마다 Claude 가 알아서 갱신하고 이렇게 알려 줍니다.

> 개발일지에 이렇게 적었습니다: "신고 화면에서 설비를 픽토그램으로 고르는 부분을 만들었다"

읽어 보고 다르면 고쳐 달라고 하면 됩니다.

### 내 파일은 어디

```
docs/devlog/<내브랜치이름>.md
```

예를 들어 브랜치가 `feature/classyb` 이면 `docs/devlog/classyb.md` 입니다.

**사람마다 파일이 하나씩입니다.** 같은 파일을 네 명이 고치면
개발일지에서 충돌이 나는데, 그게 제일 허무한 충돌이라서요.

---

## 틀

[`devlog/_template.md`](devlog/_template.md) 와 같습니다.

```markdown
## 2026-08-19

**한 것**
- (무엇을 만들었는지 한 줄씩)

**막혔던 것 / 어떻게 풀었는지**
-

**다음에 할 것**
-
```

**새 날짜를 위에 쌓습니다.** 최근 것이 맨 위에 오게요.

---

## 예시

```markdown
## 2026-08-21

**한 것**
- 위험요소 신고 화면에서 설비를 픽토그램으로 고르는 부분을 만들었다
- 접수를 누르면 목록에 뜨고, 새로고침해도 남는 것까지 확인했다

**막혔던 것 / 어떻게 풀었는지**
- 설비 목록이 안 나와서 한참 봤는데, 예시 데이터를 안 채운 상태였다
  로그인 화면에서 "예시 데이터 채우기"를 먼저 눌러야 한다
- 신고에 내 이름을 넣으려다가, 신고는 익명이 기본이라는 규칙을 보고 뺐다

**다음에 할 것**
- 음성메모 버튼 (녹음까지는 말고 자리만)
- 접수 상태 배지

---

## 2026-08-20

**한 것**
- 노동자 홈 화면의 안전 문구 배너와 메뉴 4개를 만들었다

**막혔던 것 / 어떻게 풀었는지**
- 배지 색을 직접 정하려다가 UI.okBadge 를 쓰면 된다는 걸 알았다

**다음에 할 것**
- 신고 화면
```

---

## 잘 쓰는 요령

**짧게.** 길면 아무도 안 씁니다. 한 줄씩이면 충분합니다.

**"막혔던 것"을 빼먹지 마세요.** 여기가 제일 값나가는 부분입니다.
잘 된 건 코드를 보면 알지만, 헤맨 과정은 적어두지 않으면 사라집니다.

**전문 용어를 안 써도 됩니다.** "그 파란 버튼 눌렀을 때 아무것도 안 일어나던 거" 라고 써도
나중에 본인은 알아봅니다.

**날짜를 빠뜨리지 마세요.** 발표 준비할 때 순서가 중요해집니다.
