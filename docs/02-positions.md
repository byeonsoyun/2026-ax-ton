# 02. 포지션 카드

네 명이 각자 무엇을 맡는지, **어떤 파일을 열고 어떤 파일은 열지 않는지** 적었습니다.

> **핵심 규칙: 1화면 = HTML 1개 + JS 1개, 주인은 1명.**
> 내 카드에 없는 파일은 열지 마세요. 그것만 지키면 충돌이 안 납니다.

---

| 포지션 | 담당자 | 브랜치 | 맡는 화면 |
|---|---|---|---|

| **P2** 노동자 생활 화면 | *(미정)* | | `home` · `report`(기능8) · `talk`(기능7) · `my` |
| **P3** 담당자 화면 | *(미정)* | | `dashboard`(기능6) · `content`(기능2) |
| **P4** 증빙과 검수 | *(미정)* | | `proof`(기능5) · `library`(기능9) |

**트랙은 2대 2입니다.** P1·P2 가 노동자 화면(`src/worker/`), P3·P4 가 관리자 화면(`src/admin/`).

### 아직 내 포지션이 안 정해졌다면

**표가 비어 있어도 그냥 시작하시면 됩니다.**

Claude Code 를 열면 브랜치를 확인하고, 포지션이 기록돼 있지 않으면
**아직 아무도 안 가져간 포지션만 골라서 여쭤봅니다.**
고르시면 `docs/devlog/<내브랜치이름>.md` 에 기록해 두고 다음부터는 묻지 않습니다.

누가 무엇을 가져갔는지는 `docs/devlog/` 안의 파일들을 보면 됩니다.
각 파일 맨 위에 `포지션:` 이 적혀 있습니다.

> 팀에서 미리 정하셨다면 위 표의 빈칸을 채워 두시는 편이 확실합니다.

### 다른 포지션과 만나는 지점

- P3 의 `content`(기능2)가 만든 `courses` 를 내 `learn` `quiz` 가 읽습니다

**즉 내가 `progress` 모양을 바꾸면 P3·P4 화면이 깨집니다.** 바꾸기 전에 알리세요.

### 기능3 `learn` — 안전교육 수강

내 공정의 설비에 맞는 교육을 내 언어의 음성과 그림으로 듣습니다.

1. `Store.courses.load()` 에서 내 공정 설비의 교육을 골라 목록으로 보여 준다
2. 수강 여부(`progress` 에 `learnedAt` 이 있는지)를 표시한다
3. 고르면 `phraseIds` 가 가리키는 문구를 언어별 음성·그림으로 진행한다
   — **`library` 에서 `status === 'reviewed'` 인 것만** 안전 지시로 띄운다
4. 다 들으면 `progress` 에 `learnedAt` 을 남기고 `quiz.html` 로 넘긴다

**완료 기준** 교육을 하나 골라 끝까지 듣고 나면 이해도 검증 화면으로 넘어간다.

### 기능4 `quiz` — 이해도 검증 (제품의 심장)

**글자를 한 자도 읽지 않고 끝낼 수 있어야 합니다.**

문항 3유형 (`seed.js` 의 `COURSES[].quiz` 에 모양이 있습니다)

| type | 무엇 | 데이터 |
|---|---|---|
| `hotspot` | 사진에서 위험 지점 터치하기 | `answer: { x, y, r }` — 퍼센트 좌표 |
| `choice` | 올바른 작업 고르기 | `options: []` · `answer: 인덱스` |
| `match` | 보호구 연결하기 | `pairs: [[작업, 보호구], ...]` |

1. 문항을 음성으로 읽어 준다 (안내에 음성 병행)
2. 답을 채점하고 점수를 낸다
3. `progress` 의 `quiz` 에 `{ score, passed, answers, at }` 을 남긴다
4. **통과하지 못하면 `passed: false` 로 남기고 교육 완료로 기록하지 않는다**
5. 미통과 화면에 **"노동자의 실패가 아니라 교육의 실패"** 라는 뜻이 드러나게 쓴다

**주의** 최초 통과율이 100% 면 문항이 쉬운 것이라 **지표 실패**로 봅니다 (목표 70~85%).

**완료 기준** 문항 3유형이 전부 동작하고, 미통과 시 `passed: false` 가 저장된다.

**담당: *(미정)* · 브랜치: `feature/`**

화면 수는 넷으로 가장 많지만, 하나하나는 어렵지 않습니다. 게시판과 폼이 대부분입니다.

### 데이터

**읽는 키** `Store.setup` `Store.courses` `Store.progress` `Store.posts` `Store.reports`
**쓰는 키** `Store.reports` `Store.posts`

### 다른 포지션과 만나는 지점

- 내 `home` 은 P4 의 `library` 문구를 배너로 띄웁니다

### `home` — 홈

1. 검수 완료된 안전 문구 배너 (음성 버튼 포함)
2. 이번 교육 상태 — 수강 → 검증 → 완료 3단계
3. 메뉴 네 갈래 — 수강 · 신고 · 소통 · 마이
4. 번역이 이상하면 알려 달라는 안내

**글자를 읽지 않고도 어디로 가야 할지 알 수 있어야** 하므로 메뉴는 픽토그램과 음성을 함께 씁니다.

### `report` — 기능8 위험요소 신고

1. 공장·설비 선택 (그림 목록 — `Store.setup.load().equipments`)
2. 위험유형 선택 (픽토그램 — `Store.HAZARDS`)
3. 음성메모 (선택)
4. 접수 → `Store.reports` 에 저장
5. 아래에 내 신고 목록과 접수 상태

> ★ **신고는 익명이 기본입니다.**
> `reports` 에 신고자를 식별할 수 있는 값을 **절대 넣지 마세요.**
> 익명성이 깨지면 신고가 멈추고, 재해 감소의 선행지표도 함께 사라집니다.

### `talk` — 기능7 현장 즉시 소통

게시판입니다. 게시글 형식은 `제목 · 작성자 · 작성일 · 조회수 · 댓글`.

1. 글 목록
2. 글쓰기 — 이름을 밝히거나 **익명**으로
3. 댓글

### `my` — 마이페이지

1. 회원정보 (`Auth.current()`)
2. 수강 이력 — 수강 여부와 검증 결과 (`Store.progress`)
3. 수강 증빙 출력 버튼
4. 신고 이력

> ★ 증빙은 **생성 후 수정할 수 없고**, 미이수 항목을 숨기는 경로를 만들지 않습니다.

**완료 기준** 신고를 접수하면 목록에 뜨고, 새로고침해도 남아 있다. 게시글과 댓글이 저장된다.

### `proof` — 기능5 교육 증빙 생성

**증빙 작성 시간을 2시간에서 5분으로 줄이는 것이 도입의 현실적인 이유입니다.**

1. 일시 · 언어 · 문항 · 점수 · 서명을 담은 교육일지를 만든다
2. PDF 는 **브라우저 인쇄**로 충분합니다 — `window.print()` + `@media print` CSS.
   **외부 라이브러리를 넣지 마세요** (외부 요청 0건 규칙)

> ★ **생성된 기록은 수정할 수 없습니다.**
> ★ **미이수자와 이해도 미달자를 문서에서 숨기는 경로를 만들지 마세요.**
> ★ **"면책" 표현을 쓰지 않습니다** — 교육 실시의 증빙일 뿐 법적 책임을 대신하지 않습니다.

### `library` — 기능9 안전 문구 라이브러리 (운영자)

**사용자에게 보이지 않지만 제품 신뢰의 단일 최대 요인입니다.**

| 순서 | 블록 | 핵심 |
|---|---|---|
| 0 | `AI 여기까지` 고지 | 초안 · 역번역 대조 · 음성합성까지가 AI. **승인은 사람** |
| 1 | **오역 신고 큐** | 본문 맨 위. 접수 순간 `사용 중지` |
| 2 | 검수 판정 (역번역 대조) | 원문 ↔ 역번역을 나란히, 뒤집힌 부분 강조 |
| 3 | 문구 목록 | 언어별 검수 상태 칩 |
| 4 | 라이브러리 상태 | 완료 / 대기 / 중지 개수 |

## 작업 순서 (모든 포지션 공통)

1. **읽기** — `docs/01-project-map.md` 와 내 담당 파일의 껍데기를 연다.
   각 파일 맨 위 주석에 담당·기능번호·읽는 키·쓰는 키가 적혀 있다
2. **띄우기** — `src/index.html` 을 열고 예시 데이터를 채운 뒤 내 계정으로 로그인해
   지금 화면이 어떤 상태인지 눈으로 본다
3. **한 덩어리씩** — 화면 하나를 통째로 만들려 하지 말고, 블록 하나씩 붙인다.
   한 블록이 동작하면 거기서 저장(commit)한다
4. **확인** — 새로고침해도 남아 있는지, 콘솔에 빨간 오류가 없는지
5. **기록** — Claude 가 개발일지에 적어 준다. 한 줄 확인만 하면 된다
