## 2. 화면 11 — 시작 (진입 분기점)

**역할을 먼저 고르고 로그인**하는 구조입니다.
담당자와 운영자는 로그인 후 도착 화면이 다르기 때문입니다.

| 블록 | 내용 |
|---|---|
| 헤드라인 | `2시간 → 5분` (증빙 작성 시간). 도입의 유일한 현실적 유인 |
| 역할 선택 | 사업장 담당자 / 시스템 운영자 → 아래 안내문이 “대시보드로” ↔ “문구 라이브러리로”로 바뀜 |
| 로그인 | 업무용 이메일 + 비밀번호. **운영자 선택 시에만** 2단계 인증 안내가 나타남 |
| 회원가입 | 이름 · 회사/기관명 · 직책(4종) · 사업장 규모 · 이메일 · 비밀번호 + “등록 안 한 언어는 이후 어떤 화면에도 안 나온다” 경고 |
| 범위 고지 | **합니다 / 하지 않습니다** 2단 — 공식 인정 기관·통역사 미대체, 위치·근태 미기록, 점수의 인사 활용 없음 |

직책 선택지는 `안전 담당자(겸직)` / `현장 관리자·생산팀장` / `사업주·대표` / `시스템 운영자(내부)`
— PRD 페르소나 C의 “겸직”을 그대로 살렸습니다.

**PC 적응**: 좌측 짙은 패널에 헤드라인·범위 고지, 우측 흰 패널에 역할 선택·탭·폼.
짧은 입력(이름·회사명, 직책·규모, 이메일·비밀번호)은 두 칸씩 묶었습니다.

## 3. 화면 12 — 담당자 대시보드 (기능6)

문서가 *“핵심 화면은 이수율이 아니라 언어별·항목별 취약점”* 이라고 못 박아서,
**정보 위계를 그 문장에 맞춰 뒤집었습니다.**

| 순서 | 블록 | 비중 |
|---|---|---|
| 0 | `AI 개입 없음` 고지 | 한 줄 |
| 1 | 이수 현황 (완료 9/12 · 미통과 2 · 미수강 1 · 최초 통과율 75%) | 작은 타일 |
| 2 | **이해도 취약 항목** — 언어×항목 정답률 막대 5줄 | **가장 큼** |
| 3 | 조치 대상 — 재교육 지시 / QR 재발송 | PC는 표, 모바일은 리스트 |
| 4 | 위험요소 신고 큐 (익명) | PC는 우측 패널 |
| 5 | 다음 교육 기한 (D-47 / D-6 / 미정) | PC는 우측 패널 |
| 6 | 교육 증빙 생성 진입 | 카드 |

- 취약 항목에는 문서의 예시(**“인도네시아어 화재 대응 40%”**)를 그대로 넣고,
  **“이 목록은 노동자 평가가 아니라 콘텐츠 개선 신호”** 문장을 화면 안에 적었습니다.
- 최초 통과율 75%는 PRD §2.2의 목표 구간(70~85%) 안에 들도록 잡은 값입니다.
  100%면 문항이 쉬운 것이라 **지표 실패**로 봅니다.
- 미통과는 **노동자의 실패가 아니라 교육의 실패**로 기록한다는 문구를 조치 대상 옆에 뒀습니다 (SCREEN 기능4).
- 개인별 점수는 담당자만 열람하며 **인사·평가 목적 내보내기를 제공하지 않는다**고 명시했습니다 (PRD §9.2).
- 증빙은 **생성 후 수정 불가**, 미이수자를 문서에서 숨기는 경로 없음을 함께 적었습니다 (SCREEN 기능5).

## 4. 화면 13 — 안전 문구 라이브러리 (기능9, 운영자)

**오역 신고가 본문 맨 위**입니다.
PRD §10에서 안전 문구 오역의 영향도가 유일하게 “치명적”이기 때문입니다.

| 순서 | 블록 | 핵심 |
|---|---|---|
| 0 | `AI 여기까지` 고지 | 초안 · 역번역 대조 · 음성합성까지가 AI. **승인은 사람** |
| 1 | 오역 신고 큐 | 접수 순간 `사용 중지` — 확인 후 내리는 순서가 아님 |
| 2 | 검수 판정 (역번역 대조) | 원문 ↔ 역번역을 나란히. 뒤집힌 부분 하이라이트 |
| 3 | 문구 목록 | 언어별 검수 상태 칩. PC는 6열 표 |
| 4 | 라이브러리 상태 / 검수 3종 설명 | PC 우측 패널 (172 완료 · 21 대기 · 3 신고 · 7 중지 / 총 200) |

역번역 예시는

> 원문 — “프레스가 멈춰도 손을 넣지 **마십시오**”
> 역번역 — “프레스가 꺼지면 손을 넣**어도 됩니다**”

부정이 뒤집혀 **정반대 지시**가 되는 경우를 사람 검수자가 잡는 장면입니다.

- 검수 상태 3종(`검수 완료` / `검수 대기` / `사용 중지`)은 SCREEN 기능9의 데이터 정의를 그대로 배지로 옮겼습니다.
- 전체 모수 200은 SCREEN §4 · 기능7의 “문구 200개가 오프라인으로 동작해야 한다”에서 가져왔습니다.
- 사용자에게 보이지 않지만 **제품 신뢰의 단일 최대 요인**이라는 이유를 화면 안에 남겼습니다.

## 5. 공통 컴포넌트

| 컴포넌트 | 설명 |
|---|---|
| `역할 칩` | 담당자(파랑) / 운영자(호박). 노동자 화면과 헷갈리지 않게 상단바를 짙은 회색으로 씀 |
| `AI 고지 배지` | 기능6은 `AI 개입 없음`, 기능9는 `AI 여기까지`. 문서가 기능마다 AI 개입 여부를 명시해서 화면에도 그대로 표시 |
| `상태 배지` | 완료 ✓ / 대기 ⚠ / 중지 ■ / 중립 ○. 아이콘 + 글자 + 색 3중이라 흑백에서도 구분됨 |
| `정답률 막대` | 낮음 / 보통 / 양호 등급 글자를 숫자 옆에 병기 |
| `처리 큐` | 신고 조치(기능8) · 오역 신고(기능9) 공용. 긴급 건은 왼쪽 굵은 선으로 구분 |
| `역번역 대조` | 원문 ↔ 역번역 2단. 왜곡 후보를 `<mark>`로 강조 |
| `데이터 표` | PC 전용. 좁아지면 가로 스크롤 |

## 6. 노동자 화면과 의도적으로 다른 점

**표 안의 보조 조작만 40px**로 낮췄습니다.
SCREEN §4의 60×60px는 **장갑 낀 현장 조작**을 전제한 규칙이라 마우스로 표를 다루는 담당자에겐 맞지 않습니다.
주요 조작 버튼(`.btn`)은 60px를 유지했고, 이유는 각 화면 캡션에 적어뒀습니다.

| 규칙 | 노동자 화면 | 관리자 화면 |
|---|---|---|
| 터치 타깃 60×60px | 전면 적용 | 주요 버튼만. 표 안 보조 조작은 40px |
| 문해력 비전제 (음성으로 완주) | 적용 | 미적용 — 노동자 화면(기능3·4·7·8) 전용 규칙 |
| 색상만으로 구분 금지 | 적용 | **적용** |
| “면책” 표현 금지 | 적용 | **적용** |

## 7. 아직 없는 관리자 화면

좌측 내비 / 하단 탭에 자리만 잡아두고 만들지 않았습니다.

- **기능1** 사업장·설비 등록 — 최초 1회 설정
- **기능2** 교육 콘텐츠 생성·승인 — QR 발급까지
- **기능5** 교육 증빙 생성 상세 — 교육일지 PDF
