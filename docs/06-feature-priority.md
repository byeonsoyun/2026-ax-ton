# 06. 기능 우선순위 — 무엇이 먼저인가

기능 목록은 `01-project-map.md` 에, 담당 구분은 `02-positions.md` 에 있습니다.
**이 문서는 그 사이의 판단을 다룹니다 — 무엇이 먼저이고, 시간이 없을 때 무엇을 빼도 되는가.**

지금 화면 11개 중 10개가 껍데기입니다. 넷이 동시에 만들다 보면
"이것도 넣을까요" 가 계속 생기는데, 그때마다 여기를 보면 됩니다.
발표에서 무엇을 말할지 고르는 근거도 여기서 나옵니다.

---

## 한눈에

| 층 | 뜻 | 대표 |
|---|---|---|
| **1층 · 필수** | **없으면 서비스가 깨진다.** 하나라도 빠지면 제품이 성립하지 않는다 | 기능1·2·3·4·5·6·8·9 · 문해력 비전제 · `Store` |
| **2층 · 사용성** | 코어는 돌지만 **있으면 훨씬 쓰기 좋다** | 기능7 · 마이페이지 · 예시 데이터 · 인쇄 증빙 · PC 레이아웃 |
| **3층 · 향후** | 지금 범위 밖. **다음 단계** | 서버·DB · 현장 실사진 · 오프라인 · 설비 앞 QR |

> **한 줄 기준**
> 1층은 *빼면 제품이 아니게 되는 것*, 2층은 *빼면 불편해지는 것*, 3층은 *지금은 못 하는 것*.

# 1층 · 없으면 서비스가 깨지는 것

## 1-1. 뼈대 — 이게 없으면 화면이 열리지 않는다

| 무엇 | 없으면 |
|---|---|
| **로그인 역할 분기 + 화면 가드** (`Auth.require()`) | 노동자가 관리자 대시보드에 들어갑니다. 역할이 갈리는 것이 이 서비스의 구조 자체입니다 |
| **`Store` 8개 키 데이터 계층** | 두 팀이 만나는 유일한 지점입니다. 화면 코드가 `localStorage` 를 직접 부르면 나중에 서버를 붙일 수 없습니다 |
| **노동자 홈** | 글자를 읽지 않고 길을 찾는 진입점입니다. 없으면 어느 화면으로 가야 할지 알 방법이 없습니다 |
| **외부 요청 0건 · `innerHTML` 금지 · ES 모듈 금지** | 하나만 어겨도 `file://` 에서 화면이 안 뜨거나 깨집니다. "인터넷 없이 그냥 열린다"가 이 프로젝트의 확인 방법 전체입니다 |

> ES 모듈로 시작했다가 `file://` 에서 CORS 로 막혀 전부 `var X = (function(){...})()` 로
> 되돌린 기록이 `devlog/byeonsoyun.md` 에 있습니다. 같은 길을 다시 가지 마세요.

## 1-2. 기능 — 이게 없으면 제품이 성립하지 않는다

기능 9개 중 **8개가 1층**입니다. 서로가 서로의 입력이라 하나가 비면 뒤가 다 빕니다.

| 기능 | 화면 | 없으면 |
|---|---|---|
| **기능1** 사업장·설비 등록 | `admin/setup` | 사업장·언어·공정·설비가 없으면 교육을 만들 수도 들을 수도 없습니다. **여기서 등록하지 않은 언어는 이후 어떤 화면에도 나오지 않습니다** |
| **기능9** 안전 문구 라이브러리 | `admin/library` | 검수된 문구가 없으면 안전 지시를 띄울 근거가 없습니다. 사용자에게 보이지 않지만 **제품 신뢰의 단일 최대 요인**입니다 |
| **기능2** 교육 콘텐츠 생성·승인 | `admin/content` | `courses` 가 비면 노동자의 `learn` `quiz` 가 빈 화면입니다 |
| **기능3** 안전교육 수강 | `worker/learn` | 이해를 검증할 대상이 되는 교육 그 자체입니다 |
| **기능4** 이해도 검증 | `worker/quiz` | **제품의 심장.** 이게 없으면 서명 시스템이 하나 더 생긴 것뿐입니다 |
| **기능5** 교육 증빙 생성 | `admin/proof` | 사업주 쪽 도입 유인이 0 이 됩니다. 증빙 작성 2시간 → 5분이 **유일한 현실적 유인**입니다 |
| **기능6** 담당자 대시보드 | `admin/dashboard` | 언어별·항목별 취약점이 보이지 않으면 교육을 고칠 신호가 없고, 개선 루프가 닫히지 않습니다 |
| **기능8** 위험요소 신고 | `worker/report` | 재해 감소의 **선행지표**가 사라집니다. 사고가 난 뒤의 통계만 남습니다 |

**의존 순서** — 기능1 → 기능9 → 기능2 → 기능3 → 기능4 → 기능5·6.
앞이 비면 뒤는 만들어도 화면에 아무것도 안 뜹니다.
(`src/assets/seed.js` 의 예시 데이터가 이 순서를 건너뛰고 개발할 수 있게 해 줍니다 → 2층)

## 1-3. 원칙 — 이게 깨지면 대상 사용자가 못 쓴다

노동자 화면에서 **하나라도 어기면 우리가 만든 이유가 사라집니다.**

| 원칙 | 깨지면 |
|---|---|
| **문해력 비전제** — 음성 병행 · 픽토그램 | 입국 3개월 차 크메르어 사용자가 완주할 수 없습니다. 글자를 한 자도 읽지 않고 끝낼 수 있어야 합니다 |
| **터치 타깃 60×60px** (노동자 화면 전면) | 장갑 낀 손으로 못 누릅니다 |
| **색상만으로 구분 금지** — 아이콘 + 글자 + 색 3중 | 흑백 인쇄나 색약에서 상태의 뜻이 사라집니다 |
| **6개 언어** (크메르 · 인도네시아 · 베트남 · 네팔 · 태국 · 한국) | 한 언어라도 빠지면 그 사람에게는 서비스가 없는 것과 같습니다 |
| **문항 3유형이 비문자 조작** — `hotspot` · `choice` · `match` | 문항이 글로 돌아가는 순간 기능4가 기존 필기시험이 됩니다 |

## 1-4. 원칙 — 이게 깨지면 제품의 전제가 무너진다

기술적으로는 동작하지만 **제품으로서는 죽는** 항목입니다.

| 원칙 | 왜 |
|---|---|
| **`status === 'reviewed'` 인 문구만 안전 지시로** | 오역이 그대로 사고가 됩니다. `ph-3` 처럼 부정이 뒤집히면 정반대 지시가 됩니다 |
| **위험요소 신고는 익명** — `Store.reports` 에 신고자 식별값 금지 | 익명성이 깨지면 신고가 멈추고, 재해 감소의 선행지표도 함께 사라집니다 |
| **외국인등록번호 · 여권번호 미수집** | 사업장 내 식별번호로 충분합니다. 받는 순간 다른 종류의 위험을 만듭니다 |
| **증빙 수정 불가 · 미이수 은닉 경로 없음** | 숨길 수 있는 증빙은 증빙이 아닙니다 |
| **"면책" 표현 금지** | 증빙은 교육 실시의 기록일 뿐 법적 책임을 대신하지 않습니다 |
| **개인 점수의 인사·평가 목적 내보내기 없음** | 감시 도구가 되는 순간 제품의 전제가 무너집니다 |
| **AI 경계 표시** — 기능9 `AI 여기까지`(승인은 사람) · 기능6 `AI 개입 없음` | AI 가 어디까지 관여했는지 화면에서 보이지 않으면 안전 정보를 신뢰할 근거가 없습니다 |
| **미통과는 노동자의 실패가 아니라 교육의 실패로 기록** | 노동자를 탓하는 도구가 되면 아무도 솔직하게 답하지 않습니다 |
| **최초 통과율 100% 는 지표 실패** (목표 70~85%) | 전원 통과는 문항이 쉬운 것이고, 그러면 검증한 것이 없습니다 |

> 위 문장들 중 **화면 안에 그대로 적어야 하는 것**이 있습니다.
> "이 목록은 노동자 평가가 아니라 콘텐츠 개선 신호입니다" 같은 문장은 기획에서 온 것이라
> 목업에서 옮겨 올 때 빼지 마세요.

# 2층 · 있으면 더 쓰기 좋아지는 것

**빠져도 제품은 돕니다.** 1층이 다 되기 전에는 여기에 시간을 쓰지 마세요.

## 2-1. 노동자 쪽

| 무엇 | 있으면 |
|---|---|
| **기능7 현장 즉시 소통** (`worker/talk`) | 교육 밖의 질문이 오갈 자리가 생깁니다. 익명으로도 쓸 수 있습니다 |
| **마이페이지** (`worker/my`) | 내 수강 이력·검증 결과·신고 이력을 한자리에서 보고 증빙을 출력합니다 |
| **홈 안전 문구 배너 + 음성 버튼** | 교육에 들어가지 않아도 오늘의 안전 지시가 눈과 귀에 한 번 닿습니다 |
| **수강 → 검증 → 완료 3단계 진행 표시** | 지금 어디까지 왔는지 글자 없이 압니다 |
| **"번역이 이상하면 알려 달라" 안내** | 오역을 가장 먼저 발견하는 사람이 노동자입니다 |

## 2-2. 담당자 · 운영자 쪽

| 무엇 | 있으면 |
|---|---|
| **조치 대상 — 재교육 지시 / QR 재발송** | 취약항목을 본 다음 한 화면에서 바로 처리합니다 |
| **다음 교육 기한 D-day** | 기한을 놓치는 사고를 줄입니다 |
| **QR 발급** | 노동자가 아이디를 타이핑하지 않고 교육에 들어옵니다 |
| **브라우저 인쇄 증빙** (`window.print()` + `@media print`) | 외부 라이브러리 없이 PDF 가 나옵니다. **외부 요청 0건 규칙을 지키면서** |
| **정답률 막대에 등급 글자 병기** (낮음/보통/양호) | 숫자를 읽지 않아도 심각도가 보입니다 |
| **처리 큐의 긴급 건 굵은 선 · 표 가로 스크롤** | 좁은 화면에서도 표가 무너지지 않습니다 |
| **역할 칩 + 짙은 상단바** (담당자 파랑 / 운영자 호박) | 노동자 화면과 헷갈리지 않습니다 |
| **표 안 보조 조작만 40px** | 마우스로 표를 다루는 담당자에게 맞춘 **의도적 예외**입니다. 주요 버튼은 60px 유지 |
| **PC / 모바일 두 벌 레이아웃** | 담당자는 사무실 PC 로, 노동자는 현장 폰으로 씁니다 |

## 2-3. 팀 개발 쪽 — 만드는 사람이 쓰는 도구도 사용성입니다

| 무엇 | 있으면 |
|---|---|
| **`seed.js` 예시 데이터 채우기** | 상대 팀 화면이 아직 없어도 개발합니다. id 가 고정값이라 서로 연결이 끊기지 않습니다 |
| **JSON 내보내기 백업** | 발표 전에 `localStorage` 가 날아가도 복구합니다 |
| **`UI` 공용 조각** (배지·칩·목록·토스트) | 각자 다시 만들면 네 화면의 디자인이 흩어집니다 |
| **`UI.warnIfBlocked()`** | 저장소가 막힌 환경(시크릿 모드 등)에서 원인을 알려 줍니다 |
| **저장 봉투 `{ v, updatedAt, data }`** | 버전 필드가 없으면 스키마가 바뀌었을 때 "캐시 지우세요" 말고는 답이 없습니다 |
| **1화면 = HTML 1개 + JS 1개 + 주인 1명** | 넷이 동시에 만들어도 충돌할 자리가 없습니다 |
| **`docs/mockups/` 목업 옮겨 오기** | 새로 만들지 않아서 훨씬 빠릅니다 |
| **개발일지 자동 기록** | 며칠 뒤 "내가 뭘 만들었더라" 가 발표 대본의 재료가 됩니다 |

# 3층 · 나중에 추가되면 좋을 것

지금은 **서버가 없고 브라우저 저장소만 있어서** 못 하는 것이 대부분입니다.
각 항목에 왜 지금은 안 되는지를 함께 적었습니다.

## 3-1. 지금 한계를 뒤집는 것

| 무엇 | 지금은 왜 안 되나 |
|---|---|
| **서버 · DB 도입** | 데이터가 브라우저 안에만 있어서 담당자 폰과 노동자 폰이 서로를 못 봅니다. `Store` 계층을 이미 만들어 뒀으니 `src/assets/store.js` 하나만 바꾸면 됩니다 |
| **현장 실사진 hotspot 문항** | `localStorage` 약 5MB 벽. 사진을 base64 로 넣으면 몇 장 만에 찹니다. **사진이 필요해지는 시점이 서버가 필요해지는 시점입니다.** 원래 "우리 공장 우리 프레스" 사진이어야 효과가 큽니다 |
| **오프라인 우선 동작** | 문구 200개가 인터넷 없이 도는 것이 원래 요구입니다. Service Worker + 음성 캐싱이 필요한데 `file://` 에서는 등록되지 않습니다 |
| **실제 6개 언어 음성** | 지금은 브라우저 음성합성 수준입니다. 원어민 녹음이나 검수된 합성 음성은 파일 배포가 필요하고, **음성도 문구처럼 검수 상태를 가져야** 합니다 |

## 3-2. 신뢰 루프를 닫는 것

| 무엇 | 왜 |
|---|---|
| **노동자 → 운영자 오역 신고 직결** | 지금은 홈에 "이상하면 알려 달라" 는 안내만 있습니다. 한 번 눌러 신고하면 기능9 큐에 바로 꽂히고 그 문구가 즉시 `stopped` 가 되는 경로가 필요합니다 |
| **익명 유지 회신 채널** | 처리 결과를 돌려주지 못하면 신고 동기가 식습니다. 신고자를 식별하지 않는 티켓 번호로 "조치됐습니다" 만 회신 |
| **증빙 위조 검증** | 지금은 브라우저 인쇄 PDF 입니다. 생성 시점 해시·타임스탬프를 남겨 "수정 불가" 원칙을 기술로 뒷받침 |
| **문항 난이도 자동 관측** | 최초 통과율이 70~85% 밖으로 나가면 담당자에게 경고. 사람이 매번 눈으로 볼 필요가 없게 |

## 3-3. 현장 운영을 넓히는 것

| 무엇 | 왜 |
|---|---|
| **설비 앞 QR · NFC 태그** | 프레스 앞에서 폰을 대면 그 설비 교육이 바로 뜹니다. 기능2에 QR 발급이 이미 있으니 자연스러운 다음 걸음 |
| **다중 사업장 · 협력업체 계층** | 본사 ↔ 지사 ↔ 협력업체 구조와 사업장 간 취약항목 비교 |
| **언어 확장 + 국가별 안전기준 매핑** | 현재 6개 언어. 같은 위험도 나라마다 다른 관행이 있습니다 |
| **재교육 지시 자동화** | 대상자·항목·기한이 자동으로 묶여 나오게. 단 **추천까지만, 지시는 사람이** — 기능6의 `AI 개입 없음` 원칙 유지 |
| **교육 기한 알림** | 화면에서만 보여 주는 게 아니라 담당자에게 먼저 알립니다 |
| **감독기관 제출 서식 연동** | 표준 서식으로 바로 내보내기. **"면책" 표현 금지는 그대로** |
| **접근성 확장** | 난청(진동 피드백) · 저시력(고대비·확대) 등 문해력 너머의 감각 대체 |

## 3-4. 관측 · 검증

| 무엇 | 왜 |
|---|---|
| **효과 측정 시계열** | 신고 건수 · 최초 통과율 · 취약항목 개선 추이. "재해가 줄었다" 를 주장하려면 선행지표의 시계열이 필요합니다 |
| **문항 · 문구 A/B** | 같은 위험을 다르게 설명한 두 버전의 정답률 비교 |

## 3-5. 범위 안이지만 자산이 없는 것

관리자 화면 3개는 **목업이 없습니다** (`mockups/ADMIN-SCREENS.md` §7).

- 기능1 `setup` — 코드는 완료됐지만 시안 없이 만든 화면입니다
- 기능2 `content` — P3 가 참고할 시안이 없습니다
- 기능5 `proof` — P4 가 참고할 시안이 없습니다

착수 비용이 상대적으로 큽니다. 시간이 되면 시안을 먼저 그리는 편이 빠릅니다.

## 이 문서를 쓰는 법

**무엇을 먼저 만드나** — 내 담당 화면 중 1층에 있는 것부터. 2층은 1층이 동작한 뒤에.

**시간이 없으면 무엇을 버리나** — 2층부터 버립니다.
1층을 버리는 결정은 혼자 하지 말고 팀에 말하세요. 제품이 성립하지 않게 될 수 있습니다.

**발표에서 무엇을 말하나** — 1층 중 세 개입니다.
기능2(검수된 문구에서 고르기만 하는 다국어 교육 생성) ·
기능4(문해력 독립 이해도 검증) · 기능5(증빙 2시간 → 5분).

**"이것도 넣을까요" 가 생기면** — 어느 층인지 먼저 물어보세요.
1층이면 지금, 2층이면 1층이 끝난 뒤, 3층이면 이 문서 3층에 한 줄 적어 두고 넘어갑니다.
