## 2026-08-28 (오후) — 발급한 교육의 문항 수정 (C6)

**한 것**

- 발급 목록에서 **"문항 고치기"** 를 누르면 3단계 카드가 그 교육의 문항으로 바뀐다
- 할 수 있는 것 — 맨 뒤에 더하기 · **문항 내리기** · 아무도 안 푼 교육이면 진짜 지우기
- 하지 않는 것 — 순서 바꾸기 · 선택지 개수·순서·정답 번호 바꾸기
- 검사 43건 추가. 1055 → **1098건**

**★★ 진짜 일은 화면이 아니라 데이터에 있었다**

문항을 내리는 화면을 만들기 전에 이걸 먼저 봐야 했다.

```
progress.quiz.answers = [0, 1, 1]
                         ↑  이 0 은 몇 번 문항의 답인가?
```

지금까지의 답은 **"course.quiz 의 0번"** 이었다. **자리로 찾고 있었다.**

그런데 문항 하나를 내리면, 그 뒤에 푸는 사람은 **q2 · q3 만** 받는다.
그 사람의 `answers[0]` 은 **q2 의 답**이다. 자리로 찾으면 q1 을 가리킨다.
**한 칸씩 밀린다.**

밀리면 무슨 일이 일어나나 —
대시보드가 *"끼임 항목 정답률 40%"* 라고 말하는데 실제로는 **다른 문항의 숫자**다.
틀린 곳을 못 잡는 것보다, **엉뚱한 곳을 가리키는 쪽이 나쁘다.** 그걸 보고 교육을 고친다.

그래서 이렇게 했다.

- `progress.quiz.asked` — **그때 실제로 낸 문항의 id 목록**을 함께 남긴다
- 읽는 쪽은 **`Store.askedQuestion()` 하나만** 쓴다 (대시보드 2곳 · 마이페이지 1곳)
- **`asked` 가 없는 옛 기록은 지금까지처럼 자리로 찾는다.**
  이 길을 없애면 이미 쌓인 기록이 통째로 빈다

**★ 손대다가 원래 있던 버그를 찾았다**

`quiz.js` 의 `questionsOf()` 는 **채점할 수 없는 문항을 이미 걸러 내고 있었다.**
그런데 읽는 쪽 세 화면은 **걸러지지 않은 배열의 자리**로 찾고 있었다.
즉 이 어긋남은 C6 이 만든 것이 아니라 **원래 있던 것**이고,
예시 데이터가 전부 멀쩡해서 안 보였을 뿐이다. C5 때와 같은 종류다 —
**기능을 하나 붙이면 그전까지 우연히 안 보이던 것이 드러난다.**

**정한 것과 그 이유**

| 무엇 | 어떻게 | 왜 |
|---|---|---|
| 문항 더하기 | **맨 뒤에만** | 앞 문항의 자리를 건드리지 않는다 |
| 잘못된 문항 | **내린다(retired)**, 안 지운다 | 옛 기록이 가리킬 곳이 남아야 한다 |
| 푼 사람 있는 교육 | 지우기 **막는다** | 답이 어느 문항의 것인지 알 수 없게 된다 |
| 아무도 안 푼 교육 | 지울 수 있다 | 가리킬 기록이 없다 |
| 선택지·정답 번호 | **안 고친다** | 정답은 "몇 번째" 라는 번호다. 바꾸면 **틀린 작업을 맞다고 가르친다** |

**막혔던 것 / 어떻게 풀었는지**

- **`courseOf()` 가 `content.js` 에는 없었다.** 대시보드에 있는 것을 있는 줄 알고
  썼다. 검사가 "문항 목록이 비었다" 로 잡아 줬다
- **`render()` 안에서 `stopEditing()` 을 부르니 무한히 돌았다** (`stopEditing` 이
  다시 `render()` 를 부른다). 상태만 되돌리고 다음 그리기에 맡겼다
- **망가뜨리기 ④ 가 예외로 죽었다.** `asked` 를 안 남기게 하니 검사가
  `undefined.length` 를 읽었다. `(row.quiz.asked || [])` 로 감싸서
  **실패가 실패로 보이게** 고쳤다 (D2 에서도 같은 일을 겪었다 — 습관이 됐다)
- **"내린 문항을 계속 낸다" 를 처음에는 아무 검사도 안 잡았다.**
  노동자 쪽(`test-quiz.js`)에 검사가 없었다. 붙이고 나서야 잡혔다

**증빙은 어떻게 했나**

내린 문항도 **증빙에서 빼지 않는다.** 대신 *"지금은 내려진 문항입니다"* 라고 적는다.
그 문항으로 이해를 확인한 사람이 실제로 있었으니, 문서에서 빼면 증빙이 실제와 달라진다.
*숨길 수 있는 증빙은 증빙이 아니다* 가 여기에도 그대로 걸린다.

**데이터에 더한 것 (전부 추가만)**

| 무엇 | 어디 | 없어도 되나 |
|---|---|---|
| `quiz.asked` | `progress[].quiz` | 없으면 자리로 찾는다 (옛 기록) |
| `retired` | `courses[].quiz[]` | 없으면 안 내려진 것 |

키 개수는 10개 그대로다.

**남는 한계**

- **문항 문구 자체는 못 고친다.** 고치면 번역이 그대로 남아 한국어와 다른 것을
  묻게 된다. 내리고 새로 붙이는 쪽이 안전하다
- 내린 문항이 쌓이면 목록이 길어진다. 접어 두는 것은 아직 없다

**다음에 할 것**

## 2026-08-28 — 재교육 지시 (D2)

**한 것**

- 담당자가 조치 대상 표에서 **"재교육 지시"** 를 보내면,
  그 노동자 홈 **맨 위**에 뜬다
- 그 교육을 통과하면 **저절로 사라진다.** 담당자가 따로 닫지 않아도 된다
- 거둘 수 있다. 다만 **지우지 않고 `canceledAt` 만 찍는다**
- `Store.orders` 10번째 키를 처음으로 쓴다 (B3 때 자리만 열어 뒀던 것)
- 검사 47건 추가. 1008 → **1055건**

**★ 해소를 저장하지 않는다 — 진실은 한 곳에**

`orders` 에 `done: true` 를 적어 두면 편하다. 그런데 그러면 **"통과했는가" 의
답이 두 곳(`progress` 와 `orders`)에 생기고, 언젠가 어긋난다.**
`progress` 를 보고 판정한다.

```
지시를 내린 뒤(at) 그 교육을 통과했으면 → 해소
```

**★ "뒤에" 가 중요했다.** 그냥 "통과했으면 해소" 로 두면, 예전에 한 번 통과한
기록이 있는 사람에게 지시를 보내는 순간 **보내자마자 사라진다.**
담당자는 보낸 줄 아는데 노동자 화면엔 아무것도 없다. 검사로 박았다.

판정은 `Store.orderOpen()` **한 곳**에 뒀다. 담당자 대시보드와 노동자 홈이
같은 함수를 쓴다. 계산을 화면마다 두면 한쪽만 고쳐진다 (C1 의 `courseBlock`,
B1 의 `UI.dueBadge` 와 같은 이유다).

**★ 이 기능이 인사 자료가 되지 않게**

`store.js` 주석에 이미 적혀 있던 것을 코드로 지켰다.

- **누적 횟수를 세지 않는다.** "이 사람 재교육 3회" 는 인사 평가 자료다
- **사람을 줄 세우는 화면을 만들지 않는다**
- 화면에 뜻을 적었다 — *"이 교육을 다시 듣게 한다는 뜻이지
  이 사람이 못했다가 아닙니다"*

이 화면은 이미 *"개인별 점수의 인사·평가 목적 내보내기는 제공하지 않습니다"*
라고 적고 있다. 재교육 지시는 그 원칙이 가장 쉽게 무너질 자리였다.

**막혔던 것 / 어떻게 풀었는지**

- **표 안에 입력칸을 넣으려다 말았다.** 좁은 화면에서 표가 무너진다.
  표에서 사람을 고르면 **표 아래** 칸이 열리게 했다
- **★ "남의 지시는 안 보인다" 검사가 우연히 통과했다.** 예시 지시가
  **다른 공정**이라 교육 필터에 먼저 걸렸다. `workerId` 를 안 걸러도 통과했다.
  **같은 공정 · 같은 교육**으로 지시를 하나 만들어 넣으니 그제야 잡혔다.
  검사가 무엇을 지키고 있는지 확인하려면 **그 코드를 지워 보는 수밖에 없다**
- **거두기를 지우기로 바꿔 봤더니 검사가 예외로 죽었다.** 실패는 실패인데
  다음 줄이 `orders[0].canceledAt` 을 읽다가 터졌다.
  `orders[0] && ...` 로 감싸서 **실패가 실패로 보이게** 고쳤다

**★ 남는 한계 — 담당자가 남긴 말은 한국어다**

이 제품에서 가장 아픈 자리다. 담당자는 한국어로 쓰고, 받는 사람은
한국어를 못 읽는다. 번역할 방법이 없다 — **검수를 지난 문구만 안전 지시로
쓴다**는 규칙이 여기에도 걸린다. 자동 번역을 붙이면 그 규칙이 무너진다.

그래서 **조용히 두지 않는다.**

- 메모 아래에 **"담당자가 한국어로 남긴 말"** 배지를 붙인다
- 무엇을 하면 되는지는 **글이 아닌 것으로** 준다 —
  🔁 그림 · 교육 이름 · 큰 "다시 듣기" 버튼 · 음성
- 메모를 한 글자도 못 읽어도 **"이 교육을 다시 듣는다"** 까지는 갈 수 있다

제대로 풀려면 지시 문구도 라이브러리에서 골라 쓰게 해야 한다 (E층).

**데이터에 더한 것**

- `Store.orders` 를 **처음 쓴다.** 키 개수는 10개 그대로다
- `Store.orderOpen(order, progressRow)` 헬퍼 하나

**다음에 할 것**

- **C6** 발급 후 문항 수정 → D1(QR) → D3

> **이해도 검증을 통과해야 교육이 완료됩니다.** 수강만으로는 완료로 기록되지 않습니다.

**실제 홈에는 이 두 줄이 한 글자도 없었다.** 3단계 그림만 있었다.
서명은 참석의 증거일 뿐이라는 데서 출발한 제품인데, **노동자가 보는 첫 화면이
그 말을 안 하고 있었다.** 그 화면은 그냥 진도표였다.

**옮긴 것 (8가지)**

| 어디 | 무엇 |
|---|---|
| 홈 | 검증을 통과해야 완료 · 수강만으로는 아님 |
| 홈 | 검수되지 않은 번역은 안전 지시로 쓰지 않음 |
| 홈 | 오늘의 문구에 "✓ 검수 완료" 배지 |
| 홈 | 메뉴 4칸 배지 (남은 교육 수 · 익명으로 접수 · 공식 답변 표시 · 증빙 출력) |
| 대시보드 | 생성된 기록은 수정할 수 없고, 숨기는 경로는 없음 |

| 라이브러리 | 검수 완료가 아닌 문구는 어떤 화면에서도 노출되지 않음 |
| 라이브러리 | "이 화면이 왜 중요한가" 카드 |

**★ 옮기지 않은 것 — 이쪽이 더 중요했다**

시안에 있다고 다 옮기면 **화면이 거짓말을 한다.**

  대신 C7 에서 생긴 "공식 답변 표시" 를 적었다
- **"조치 결과는 신고자의 언어로 번역돼 회신됩니다"** — 회신 채널이 없다.
  익명을 지키면서 회신하는 것은 그 자체로 별도 과제다 (E층)
- **"사진 보기" 버튼** — 사진이 없다. `localStorage` 5MB 벽
- **"교육일지 PDF 만들기 (준비 중)"** — 여기는 **시안보다 앞서 있다.**
  실제로는 인쇄가 된다. 뒤로 돌릴 이유가 없다
- **목업 하단 탭 5개(문구/오역/검수/음성/배포)** — 한 화면 안 구역으로 이미 다 있다.
  탭으로 쪼개면 오역 신고를 못 보고 지나갈 수 있다

**막혔던 것 / 어떻게 풀었는지**

- **배지를 붙이고 나서 소리를 빠뜨릴 뻔했다.** 메뉴 배지를 눈에만 보이게 두면

  다만 아이콘(`✓` `●` `🕶`)은 읽지 않는다 — 소리로는 뜻이 없다.
  `replace(/^\W+/, '')` 로 잘랐다가 **한글까지 잘렸다** (JS 정규식에서 한글은
  `\w` 가 아니다). `/^[^가-힣\d]+/` 로 바꿨다
- **"0개 남음" 을 지어낼 뻔했다.** 받을 교육이 아예 없을 때도 배지를 만들면
  "0개 남음" 이라고 적힌다. 없는 것은 없다고 두는 것이 맞다. 검사로 박았다
- 곁들여 홈의 "여기부터" 칸에서 **끝난 "글자 크기 조절"(B3)** 을 지웠다

**데이터에 더한 것**

  다만 **답글만 단다** — 글쓰기 버튼을 감췄다. 여기는 노동자가 묻는 자리다
- 담당자에게는 **이름 감추기 칩을 아예 두지 않는다**
- 검사 32건 추가. 932 → **968건**, 9묶음 전부 통과

**막혔던 것 / 어떻게 풀었는지**

- **지난 세션이 여기서 세션 한도로 끊겼다.** 코드는 거의 다 돼 있는데
  커밋이 안 된 채로 작업대에 남아 있었다 (`docs/끊긴 부분.txt`).
  **먼저 손대기 전에 검사를 돌려 932건 전부 초록인 것을 확인**하고 이어갔다 —
  이걸 안 하면 뒤에 깨진 것이 내 탓인지 알 수 없다
- **★ 코드는 다 만들었는데 들어갈 길이 없었다.** `talk.html` 로 가는 링크가
  `src/worker/` 안에만 있어서, 담당자는 **주소를 직접 쳐야** 답글을 달 수 있었다.
  기능을 만들어 놓고 아무도 못 쓰는 상태였다. 대시보드에 진입 칸을 만들었다
- **★ 담당자가 들어오니 아래에 노동자 탭바가 그대로 떴다.** 탭 다섯 개가

  (그런 문구가 검수 완료로 못 올라가는 것은 원래 있던 규칙이 이어서 막는다)
- **검사 하나가 실패했는데 코드가 아니라 검사가 틀린 경우였다.**
  접수에 성공하면 폼이 비워지는데 **경고 칸도 함께 지워진다.** 검사가 접수한 뒤에
  경고를 보고 있어서 빈 문자열이 나왔다. → 경고는 접수 전에 보도록 순서를 바꿨다
- **검사가 정말 새 코드를 잡는지 확인했다.** 통과 개수가 는 것만으로는 모른다.
  `status: 'waiting'` 을 일부러 `'reviewed'` 로 바꿔서 돌려 봤더니 —
  **스택 트레이스로 터졌다.** 이미 검수 완료인 줄에는 "검수 완료" 버튼이 없어서
  없는 버튼을 누른 것이다. 잡기는 잡는데 **무엇이 깨졌는지가 안 보인다.**
  → 버튼이 없으면 그 자체를 실패로 적게 고쳤다. 이제 같은 규칙을 깨뜨리면
  **"★ 새 문구는 검수 대기로 들어간다 → 기대 waiting / 실제 reviewed"** 처럼
  이름이 붙은 실패 7건이 나온다
- **줄바꿈에서 또 한 번 걸렸다.** 어제 겪은 그 문제다. 저장소 파일은 CRLF 인데
  msys `sed` 가 지나가면서 CR 을 떨궈 놓는다. → `core.autocrlf=true` 라
  git 안에는 어차피 LF 로 들어가고, `git diff` 에 고친 줄만 잡히는 것을 확인하고 넘어갔다

**데이터에 더한 것**

- 없다. 저장 모양은 기존 문구와 똑같다 (`{ id, category, ko, status, translations, flags }`).
  `Store` 키도 그대로 8개다. **모양을 안 넓혔으니 다른 화면을 확인할 필요가 없었다**

**남는 한계 — 적어 둔다**

- **역번역을 넣는 사람과 번역을 넣는 사람이 같다.** 운영자가 번역기를 두 번 돌려
  붙여 넣으면 대조가 통과한다. 진짜 대조는 번역자와 역번역자가 다를 때 뜻이 있다.
  이건 사람 절차의 문제라 화면으로는 못 막는다
- `renderReview()` 가 역번역 없는 번역을 만나면 화면에 글자 **"undefined"** 를 찍고
  "역번역이 원문과 같습니다" 라는 **틀린 안내**까지 붙인다. 새 폼이 역번역을 강제해서
  화면으로는 만들 수 없지만, **불러오기로 남의 데이터를 넣으면 생긴다.**
  이번 커밋을 좁게 두려고 손대지 않았다
