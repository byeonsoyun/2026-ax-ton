**막혔던 것 / 어떻게 풀었는지**

- **신고 폼의 기본값을 무엇으로 둘지가 제일 어려웠다.** 특정 언어를 기본으로 두면
  손대지 않고 접수한 순간 엉뚱한 언어가 내려가고 정작 오역인 번역은 계속 현장에 나간다.
  "문구 전체" 를 기본으로 두면 한 언어의 오역으로 다른 언어 노동자까지 안전 지시를
  잃는다 — A2 를 만든 이유가 사라진다. **둘 다 조용히 잘못되므로 한 번 고르게 했다.**
  고르지 않으면 접수가 안 된다
- **문구 전체와 언어별 판정이 다를 때 무엇을 따를지.** → **엄한 쪽**으로 정했다
  (중지 > 대기 > 완료). 한국어 원문이 아직 대기인데 번역만 완료라고 쓸 수는 없고,
  문구 전체가 중지면 어느 언어로도 나가지 않아야 한다
- **"한 언어를 고쳤다" 가 문구 전체를 되살리면 안 된다.** 처음엔 `setStatus` 가
  열린 신고를 전부 닫았는데, 그러면 인도네시아어를 고친 판단으로 크메르어 신고까지
  닫혔다. 언어별 판정은 **그 언어의 신고만** 닫게 했다
- **타일에서 한 문구가 "검수 완료" 와 "사용 중지" 양쪽에 세어진다.** 처음엔 버그로
  보였는데 그게 사실이다 — ph-3 은 크메르어로 나가고 인도네시아어로는 안 나간다.
  설명 문구를 "한 언어라도 …" 로 바꿔 세는 기준을 화면에 적었다
- **한글이 콘솔에서 깨져 나와 긴 코드 블록을 문자열로 못 찾았다** (cp949).
  `function setStatus(` 부터 다음 함수 끝까지 **범위로 잡아서** 통째로 바꿨다
- 예시 데이터가 바뀌자 다른 묶음 15건이 함께 깨졌다. 전부 개수 기대값이었고,
  `ph-3` 이 두 교육에 들어가 문구 수가 3 → 4 로 늘어난 것이 원인이었다

  그건 "설계도로 읽히게" 만든 장치라, 실제 배포물에서는 벗기고
  컴포넌트 클래스(`.card` `.badge` `.field` 등)만 재사용했다
- `style-pc.css` 를 가져오려다 뺐다. `.row` `.field-row` `.main` 같은 이름이
  새 마크업과 충돌한다. 목업 전용 골격이라 지금 구조에는 안 맞는다
- 브라우저 자동화 도구가 없어서 눈으로 확인할 방법이 없었다.
  jsdom 을 스크래치패드에 깔고 실제 DOM 에서 스크립트를 돌려서 검증했다
  (기능1은 36개 항목, 구조는 61개 항목 통과)
- 저장 데이터를 `{ v, updatedAt, data }` 봉투로 감쌌다.
  버전 필드가 없으면 나중에 스키마가 바뀌었을 때
  "브라우저 캐시 지우세요" 말고는 답이 없어진다
