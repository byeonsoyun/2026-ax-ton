- 기능3 안전교육 수강을 만들었다. 내 공정 설비의 교육 목록 → 안전 문구를 한 장씩
  내 언어의 음성과 픽토그램으로 → 다 들으면 `learnedAt` 을 남기고 검증으로 넘긴다

  `hasVoice` `onVoicesReady` `voiceNote`

**막혔던 것 / 어떻게 풀었는지**
- **`feature/yesool` 이 완전히 다른 프로젝트였다.** Next.js + Supabase + TypeScript 로
  이 저장소와 공통 조상이 하나도 없었다. 팀에서 바닐라를 본선으로 유지하기로 정하고,
  거기서 쓸 만한 것만 이식했다 — 특히 **"단순 정답 확인이 아니라 결과 학습"**
  (답한 직후 그 선택이 어떤 사고가 되는지 말해 주기)은 우리 문서에 없던 좋은 아이디어였다
- hotspot 문항에 쓸 설비 사진이 없었다. 외부 이미지는 금지고 base64 사진은 5MB 를
  금방 채운다. **인라인 SVG 도해를 `viewBox="0 0 100 100"` 으로 그려서** 풀었다.
  좌표계가 곧 퍼센트라 `answer { x, y, r }` 이 화면 크기와 무관하게 같은 자리를 가리킨다
- 문항마다 정답 원 하나만 두면 "어디를 눌러야 하는지" 감이 안 왔다. 도해에 **이름 붙은
  구역**을 두고 "정답 원 안에 중심이 들어오는 구역"을 정답으로 삼았다. 구역 이름이
  `aria-label` 이 되니 화면 낭독기에서도 읽힌다. 정답 구역이 하나도 없는 교육이면
  구역을 안 쓰고 그림 아무 곳이나 짚는 방식으로 되돌린다
- 다시 풀기를 허용하면 점수가 늘 100 이 되어 담당자 대시보드의 **최초 통과율**이
  뜻을 잃는다. 한 문항에 한 번만 답하게 하고, 다시 풀기는 처음부터 하도록 했다.
  그리고 `progress.quiz` 에 `attempt` 와 `firstPassed` 를 **더했다**
- 크메르어 음성이 깔린 안드로이드는 흔하지 않다. 그냥 조용히 실패하면 글자를 못 읽는
  사람은 아무것도 못 받은 채 교육을 통과한다. **한국어로 읽고 그 사실을 화면에 적게** 했다
- 브라우저 자동화 도구가 없어서, 스크래치패드에 jsdom 을 깔고 실제 DOM 에서 돌려
  검증했다 (기능3 42건 · 기능4 88건 · 회귀 42건 통과)

**★ 팀에 공유할 것 — 공용 파일을 두 군데 고쳤다**
- `assets/ui.js` 음성 함수 6개 **추가**. 기존 21개 함수는 그대로라 다른 화면은
  영향 없다. P2 의 홈 배너·신고 음성메모도 그대로 쓰면 된다
- `progress.quiz` 에 `attempt` · `firstPassed` **추가**. 기존 네 필드
  (`score` `passed` `answers` `at`)는 그대로다.
  → **P3 는 최초 통과율을 `firstPassed` 로 세면 됩니다**
- `courses.quiz` 에 선택지별 결과 문구 `results` 와 해설 `why` 를 예시로 넣었다.
  둘 다 없어도 동작한다. → **P3 의 기능2 가 앞으로 이 문장을 함께 만들면 좋겠습니다**
- 문항 자체의 다국어화는 `courses` 모양을 넓혀야 한다. 지금은 문항을 한국어로 읽고
  픽토그램과 그림이 문해력을 받친다. → **기능2(P3)와 같이 정해야 할 일**

  화면 11개 자리를 전부 만들었다 (기능1 완성 + 껍데기 10)
- 공용 모듈 4개를 만들었다 — `store.js`(데이터 8개 키) `auth.js`(로그인·가드)
  `ui.js`(배지·칩·목록) `seed.js`(예시 데이터)
- 팀 개발 문서를 만들었다 — `CLAUDE.md` + `docs/` 6개 + 개발일지 틀

**막혔던 것 / 어떻게 풀었는지**
- ES 모듈(`import`/`export`)로 시작했는데 `file://` 에서 CORS 로 막혔다.
  "인터넷 없이 그냥 열린다"는 성질을 잃고 싶지 않아서
  `var X = (function(){...})()` 형태의 클래식 스크립트로 전부 바꿨다
- 기존 프로토타입 HTML 이 폰 목업 껍데기(`.stage > .phone > .app`)를 두르고 있었다.
  그건 "설계도로 읽히게" 만든 장치라, 실제 배포물에서는 벗기고
  컴포넌트 클래스(`.card` `.badge` `.field` 등)만 재사용했다
- `style-pc.css` 를 가져오려다 뺐다. `.row` `.field-row` `.main` 같은 이름이
  새 마크업과 충돌한다. 목업 전용 골격이라 지금 구조에는 안 맞는다
- 브라우저 자동화 도구가 없어서 눈으로 확인할 방법이 없었다.
  jsdom 을 스크래치패드에 깔고 실제 DOM 에서 스크립트를 돌려서 검증했다
  (기능1은 36개 항목, 구조는 61개 항목 통과)
- 저장 데이터를 `{ v, updatedAt, data }` 봉투로 감쌌다.
  버전 필드가 없으면 나중에 스키마가 바뀌었을 때
  "브라우저 캐시 지우세요" 말고는 답이 없어진다
